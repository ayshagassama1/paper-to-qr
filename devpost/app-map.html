Paper to QR: app map

A restaurant manager photographs a paper or chalkboard menu and gets an editable digital menu, a code to come back with, and a QR code for customers. No typing, no account.

Snapshot of commit e69eb9a (2026-10-26). The code can drift from this map after later changes.

The main pieces

Frontend

React, TypeScript, Vite, Tailwind and restyled shadcn/ui in frontend/src/. Served from S3 through CloudFront.

Backend

FastAPI in backend/app/, run on Lambda through Mangum behind an HTTP API at /api/*.

External services

Claude Haiku 5.5 reads the photos. MongoDB Atlas stores one document per restaurant. Photos are never stored.

One action, end to end: a photo becomes a menu

This is the kernel of the app: the manager clicks Read my menu and lands on the Menu screen with the Menu ready badge.

Reference route (3 stops)

A route to follow in the editor when you want to see how this action works. It was not toured as a guided activity; use it as a starting point.

  1. The form sends the photos

    frontend/src/components/NewRestaurantForm.tsx, search async function submit; then frontend/src/lib/api.ts, createRestaurant

    Each photo goes through compressImage (canvas, about 1600 px JPEG, which also drops EXIF and GPS data) so the upload stays under the Lambda limits. createRestaurant uses XMLHttpRequest so the form can switch from "Uploading photos..." to "Reading your menu..." as soon as the bytes are sent.

    Show the snippet 
    const compressed = await Promise.all(photos.map(compressImage))
onCreated(await createRestaurant(name.trim(), compressed, () => setStep("reading")))

  2. The route reads and saves the menu

    backend/app/routes/restaurants.py, create_restaurant; then backend/app/extraction.py, extract_dishes

    The route checks the name and the photo count, hands the photo bytes to extract_dishes, then builds the document with a unique slug and code (backend/app/codes.py) and inserts it. extract_dishes sends the images and the INSTRUCTION prompt to Claude with a structured output schema, and returns an empty list on any failure so the manager can still add dishes by hand.

    Show the snippet 
    # Photos stay in memory for the extraction only; they are never stored.
extracted = extraction.extract_dishes([image.file.read() for image in images])
...
restaurants.insert_one(doc)
return to_private(doc, extraction_empty=not doc["dishes"])

  3. The Menu screen shows the result

    frontend/src/pages/HomePage.tsx, search justCreated; then frontend/src/components/MenuEditor.tsx, search Menu ready

    HomePage swaps the form for MenuEditor inside the home panel. MenuEditor shows the name, the apricot badge (only when justCreated), one DishRow per dish, and the QrPanel with the code and the QR code built from window.location.origin plus the slug.

A practice to reuse

Set the visual defaults before any screen, then check the UI with your eyes

The question: does a generic, "AI-made" interface come from vague instructions or from the agent? (devpost/spec.md > Decisions and Open Issues)

The decision: frontend/src/styles/theme.css was written before the first screen, with the palette, fonts, radius, usage rules (apricot only for "Menu ready") and a list of things to avoid (devpost/spec.md > Look and Feel > Hard rules for the build agent).

The evidence: shadcn init installed Geist, a neutral grey theme and a dark mode by default, all of which had to be replaced. Later, the TypeScript build passed every time, while desktop and mobile screenshots caught a stretched QR code, a delete button in the wrong color and an unreadable tab on hover.

On the next project: write the design tokens and the "avoid" list first, give the agent a concrete reference and say what to keep and change, and make visual checks (screenshots at phone and desktop widths) part of the verification of every UI step, not just the build.

Run it again

Requires Node 20+, Python 3.12, a MongoDB Atlas cluster and an Anthropic API key. Copy backend/.env.example to backend/.env and fill it in.

# Backend
cd backend
pip install -r requirements.txt -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000

# Frontend (second terminal)
cd frontend
npm install
npm run dev -- --host

# Tests
cd backend && pytest
cd frontend && npm run build

Open http://localhost:5173, or the LAN address Vite prints to scan the QR code with a phone. Deployment steps are in README.md and devpost/spec.md > Where It Runs and How Someone Tries It.
