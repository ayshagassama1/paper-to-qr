Paper to QR

A restaurant manager photographs their menu and gets an editable digital menu, a code and a printable QR code, with no typing and no account.

The kernel
No typing, no account.

Retyping a whole menu into an app is friction. Here, a photo of the chalkboard is enough: the list of dishes and prices appears, and the manager can try it right away, with no hassle.

The loop

the kernel: photo → list first visit the reason to come back

Who it's for

The manager

Restaurant, café or bistro with a menu of the day

The menu changes often, and prices follow rising ingredient costs. Today it's written in chalk or printed, with the old price crossed out and the new one written next to it.

The customer

At the table, phone in hand

Scans the QR code and sees the list of dishes with prices. Nothing more.

What "working" means

I upload an image and get a list of dishes with their prices, with the option to edit the name/price in case the OCR misread it. And at the bottom, a downloadable QR code to print for the end customer.
  1. A real menu, chalkboard or paper, is photographed.
  2. The list of dishes and prices appears: the "oh, that's cool" moment.
  3. Anything the OCR misread gets fixed.
  4. The code and QR code are generated.
  5. The QR code is scanned with a real phone and the digital menu shows up.
  6. It's all deployed so the judges can see the site.

The boundary

Now: the proof of concept7
  • Upload one or more photos, then extract dishes and prices with OCR
  • Editable list: change a dish's name or price, delete a dish
  • Generate a code and a downloadable QR code pointing to /restaurant-slug
  • Returning manager: pastes the code and finds the restaurant name, dishes and QR code
  • Public page /restaurant-slug: dishes and prices
  • Data stored in MongoDB Atlas: restaurant name, code, QR code and menu
  • React + FastAPI, deployed on CloudFront + Lambda (learner's choice, already used to AWS)
Later3
  • Add a dish by hand, or replace the menu with a new photo (to settle in the PRD)
  • Customizing the customer page (colors, logo)
  • Categories, descriptions, allergens
Cut, and why2
  • Authentication and accounts: this is the kernel. No account, the code is enough.
  • Storing images: photos are used only for extraction, then discarded.

Inspiration & identity

Very simple, basic, clean. Easy to use without having to look up "how to".

References: Uber and Instagram, for the je ne sais quoi that sets them apart from clean interfaces that all look alike. Mobbin as a possible source.

To be explored further in the PRD.

Why it matters

I find this project is a simple solution to a fairly common problem.

Most restaurants the learner goes to still use paper menus. The project is also a playground for learning how to get an interface from an agent that doesn't feel like AI slop.

Risk to keep in mind

Extracting text from a handwritten chalkboard is the most uncertain part, and it's also the heart of the demo. The editable list is the safety net. The engine (classic OCR or a vision model) will be chosen in the spec.
